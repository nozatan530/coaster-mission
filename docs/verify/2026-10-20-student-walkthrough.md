# 利用テスト：高校生が1人で使う（2026-10-20）

記録なしの状態から、スタート → 練習3つ → 本番設計・試走（10回連続を2回）→ 記録表 → レポート → やり直し の順に、内蔵ブラウザで操作した。画面幅は PC（約830px）とスマホ（360px）。あわせてコードを読んで点検した。

- コンソールのエラー：なし
- 横のはみ出し（360px）：全画面なし
- 物理の確認用3設計（`npm run check:physics`）：一致

## 問題なく動いたこと

- 予想を空欄・空白だけで送ると止まる。入力すると保存され、練習ステージへ進む
- 予想を入れるまで、タブ2〜5は押しても進まない
- 練習①②③はそれぞれの部品だけで走り、通過・落下・命中の判定が出る
- レールが 6.0 m を超えると走らせるボタンが押せない
- 10回連続の結果が記録表に1行ずつ追加され、レポートにも反映される
- 「最初からやり直す」には確認ダイアログがあり、記録がすべて消える
- レポートは未記入の項目に印がつき、記入済みの数（例 2/8）が出る

| # | 場所 | 起きること | 生徒が困ること |
|---|---|---|---|
| 1 | 練習①・本番（ループ） | 高さが足りないとき、ボールがループの**頂上まで登り、速さ0で止まって**見える。棒グラフの合計（位置＋熱）が**最初のエネルギーより増える**（例 11.76 → 12.07 J/kg） | 「エネルギーが増えた」「頂上に着いたのに落ちた」と誤解する。得点の判定（落下）は正しい |

## 確かめられなかったこと

- 印刷／PDF保存の見た目（ブラウザの印刷画面は操作できないため）
- 効果音が実際に鳴るか
- iPad の Safari、Chromebook の実機での操作
- localStorage が使えない環境（コード上は例外を握りつぶして動き続ける作り）
