# ボールコースター・ミッション（coaster-mission）

## ひとことで
高校物理基礎の生徒が1人1台で、**長さ6 mのレール**を使ってボールコースターを組み、ループ・ゆっくり区間・缶当てで得点を競うアプリ。スタートを高くするほど坂にレールを取られ、エネルギーとレールの両方をどう配分するかを考える。試走と改善の記録はレポートにして提出する。

## 利用者と場面
- 高校「物理基礎」で、力学的エネルギーと斜方投射をまとめる探究的な活動。授業中に1人1台で使い、宿題で続けてもよい
- 実物のコースは作らない。設計・試走・改善はすべてアプリの中で行う
- 端末は Chromebook・iPad・スマホが混在。縦長のスマホ画面でも操作できること
- 姉妹アプリは[ジェットコースター・エネルギーラボ](https://coaster.meetupsensei.com/)（`~/code/apps/roller-coaster-energy`）。見た目（色・フォント・棒グラフ・ライト／ダーク）と単一HTMLの構成をそろえる。あちらは「すべるコースター」、こちらは「転がるボール」
- 元にした教材は NHK高校講座 物理基礎 第23回「物理で解決しよう①」の学習メモ。借りるのはゲームの枠組み（大小のループ・ゆっくり区間・飛び出すと同時に落ちる缶）だけ。本文・画像は転載しない（無断転載禁止の表示があるため）。ルール文・問い・解説はすべて新しく書く

## コースの組み方（制約）
コースの**順番は固定**し、生徒は各部品の「高さ」と「入れるかどうか」だけを決める。部品を自由に並べるエディタにはしない（スマホでも操作でき、AI Studio でも作りやすいため）。

```
スタート台 → ループ区間（なし／小／大／小と大。順番は自由）→ ゆっくり区間 → 発射台 →（空中）→ 缶
```

| 制約 | 値 | ねらい |
|---|---|---|
| 使えるレール | **6.0 m**（全員同じ） | 全部入りの設計はレールが足りない |
| 坂の傾き | 30°に固定。**高さを1 m変えるとレールを2 m使う**（上りも下りも） | 「高くすると距離が短くなる」。上り下りをくり返すほど損 |
| 支柱の高さ | 10〜150 cm。10 cm刻み（ゆっくり区間だけ5 cm刻み） | スタートの高さにも上限がある |
| 平らな部品のレール | スタート台 30 cm、ゆっくり区間 50 cm（計測区間）、発射台 30 cm | 必ず使う分 |
| 大ループ | 直径 50 cm（レール 1.57 m＋つなぎ 0.2 m）、＋30点 | 点は大きいが、レールも高さも多く使う |
| 小ループ | 直径 30 cm（レール 0.94 m＋つなぎ 0.2 m）、＋10点 | 安くて安全 |
| ループの数 | 大・小それぞれ1個まで | |

画面には常に「残りのレール ○.○ m」を表示し、超える設計は走らせられない。

## ボールと物理モデル
- 鉄球（直径約2 cm）がレールの上を**すべらずに転がる**。転がる球は回転にもエネルギーを使うので、運動エネルギーは ½mv² の 1.4 倍（7/10 mv²）になる。同じ高さの差でも、すべる物体より遅い
  - 表示の切り替えで「すべる物体だったら」と比べられる（発展）
- 摩擦などによる損失は、**レールを1 m進むごとに、高さ1.5 cm分のエネルギーが熱などに変わる**とする（棒グラフの T に積算）
- ループに入るときは、壁との衝突で運動エネルギーの約5%を失う
- ループの頂上で落ちない条件は v² ≥ gr。転がる球の場合、ループの最下点はスタートより**半径の2.7倍以上**低くなければならない（すべる物体なら2.5倍）
  - 大ループなら約68 cm、小ループなら約41 cm。損失を入れると、実際には大で約75 cm、小で約45 cm 必要
- 発射台を出たあとは、回転は関係なく、速さ v の斜方投射になる

## 得点のルール
| 項目 | 得点 |
|---|---|
| 大ループを通過 | ＋30 |
| 小ループを通過 | ＋10 |
| ゆっくり区間 | 計測区間の中央で時速5.0 km以上なら0点。そこから0.1 km/h遅くなるごとに＋1（例：4.7 km/h → 3点） |
| 缶に命中（缶の大きさ） | 小（直径6 cm）＋30／中（9 cm）＋20／大（12 cm）＋10 |
| 缶に命中（つるす高さ） | 床から140 cm ＋50／120 cm ＋40／100 cm ＋30／80 cm ＋20／60 cm ＋10 |

- 缶は**高くつるすほど発射台から遠くに置く**（発射台の先端から水平に、60 cm → 0.80 m／80 cm → 0.95 m／100 cm → 1.10 m／120 cm → 1.25 m／140 cm → 1.40 m）。**ボールが発射台を離れた瞬間に落ち始める**
  - 最上段（＋50）ばかりが得にならないようにするため（2026-10-20 変更。`docs/balance.md`）
- 発射の角度は0〜60°で、1°刻みで決める
- ゆっくり区間で止まったり坂を戻ったりしたら、そこまでの得点で終了。ループで落ちた場合も同じ
- 時速5 kmになるのは、スタートから約14 cm下がった高さ（損失なしの場合）。つまりゆっくり区間で点を取るには、ループで下がったあと**スタート近くまで登り直す**必要があり、そこでレールを使う

## 毎回のばらつき（再現性）
1回ごとに次のずれをランダムに入れる。「10回連続」で成功率と平均点を出す。
- 摩擦の大きさ：±12%程度
- ループに入るときの損失：基準の0.5〜1.5倍
- 発射の向き：上下に±1.2°程度。左右は缶までの距離 1 m あたり±2 cm程度（向きの誤差なので、遠い缶ほど外れやすい。缶が小さいほど外れやすい）

## 試算で確かめたバランス
代表的な設計を各1,000回走らせた（「理想の点」はばらつきがないときの得点）。アプリの物理モデルで `npm run balance` を実行した結果（2026-10-20、缶の距離を高さで変えたあと）。発射の角度は、どれも缶の中心へ向けている。

| 設計 | レール | 理想の点 | 平均点 | 成功率 |
|---|---|---|---|---|
| ループなし。スタート150 cm、ゆっくり区間145 cm、小さい缶を最上段に | 2.5 m | 102 | 80 | 74% |
| 大ループだけ。ゆっくり区間はあきらめる | 4.9 m | 110 | 86 | 70% |
| 小ループだけ。ゆっくり区間140 cmで27点、発射台60 cm、中の缶を最上段に | 5.6 m | 107 | 98 | 86% |
| 大＋小ループ。ゆっくり区間はあきらめ、中の缶を最上段に | 5.8 m | 110 | 98 | 83% |
| 全部入り（大＋小＋ゆっくり区間130 cm＋小さい缶） | **8.6 m（規定外）** | — | — | — |

- 構想時の試算（缶はどれも 1.0 m 先、左右±3 cm）では、平均点 83〜104 点、最上段がいつも 6〜9 点得だった。経緯は `docs/balance.md`

**ここから言えること**
- 6 mでは「全部入り」は組めない。どの戦略でも平均点は80〜98点に収まり、一つの正解に偏らない（ループなしはゆっくり区間の点の伸びしろが小さく、やや低い）
- 缶の最上段（140 cm）と1段下（120 cm）の差は、平均で1〜5点。10回連続の平均点が運だけで±9点ほど揺れるのより小さく、最上段一択にはならない
- レールが足りても、全部入りは**ぎりぎりの設計になって成功率が下がり**、平均点では安全な設計に負ける。「理想の点」と「平均点」の差が、メモのポイント3（再現性）の学びになる
- 試算はアプリの雰囲気をつかむための目安。定数は試作のときに調整する

## 学びの目的
- 力学的エネルギーには限りがあり、それをループ・ゆっくり区間・発射に配分する設計だとわかる。登り直すには高さが要り、高さを取るにはレールが要る
- ループの頂上で落ちないためには「止まらない」だけでなく「ある速さ」が必要で、そのためにスタートとの高さの差が要ると説明できる
- 転がるボールは回転にもエネルギーを使うので、すべる物体より同じ高さで遅くなることに気づく（発展）
- 摩擦・壁との衝突で力学的エネルギーが減ることを、棒グラフ（運動 K・位置 U・熱など T）で確かめられる
- 飛び出すと同時に落ちる缶には、缶へまっすぐ向ければ、速さによらず（届く範囲なら）当たる。これを斜方投射と自由落下の重ね合わせとして説明できる（モンキーハンティング）
- 同じ設計でも結果がばらつくことを知り、余裕（マージン）を持たせて成功率を上げる考え方を体験する

## 体験の流れ（利用者目線）
1. **ルールを知る**：得点表と制約（レール6 m・坂30°・支柱150 cmまで）を見る。「何点取れそうか」と「どこで点を取るか」を予想して入力する（入力しないと先に進めない）
2. **練習ステージ（3つ）**：部品を1つずつ試す。練習ではレールの制限はない
   - ループ練習：スタートの高さを変え、大小のループを通過できる境目を探す。「直径の何倍の高さが必要か」を問う
   - ゆっくり区間練習：区間の高さを5 cm刻みで変え、時速と「止まってしまう」境目を探す
   - 発射練習：発射の角度と缶の高さを変えて命中させる。「缶へまっすぐ向けると当たる」ことに気づかせる（角度を tanθ ＝ 高さの差 ÷ 缶までの距離 で計算できる）
   - 各ステージに問いを1つ置き、エネルギーの言葉で答える
3. **本番の設計**：スタートの高さ、ループの有無と各最下点の高さ、ゆっくり区間の高さ、発射台の高さと角度、缶の大きさとつるす高さを決める。横から見たコースの図と「残りのレール」が同時に変わる。走らせる前に予想得点を入力する
4. **試走**：1回ずつ走らせてアニメーションで見る。K・U・T の棒グラフと、どこで何点入ったかが表示される。失敗したときは「どこで・なぜ」の候補を示す（ループ頂上で速さ不足／ゆっくり区間で停止／缶の上を通過 など）
5. **改善**：設計を変えるときは「何を変えたか・なぜか」を一言書く（空欄でも走れるが、レポートに空欄として残る）。「10回連続」で成功率と平均点を見る。**本番の記録は10回連続の平均点**とし、1回だけの最高点では競わない
6. **レポート提出**：最終設計の図と数値、10回連続の平均点と成功率、試走の記録表、変更とその理由、最初の予想との比較、振り返りの問い3つを1枚にまとめる。足りない項目には印がつく。印刷／PDF保存／テキストのコピーで Classroom などに提出する

## 振り返りの問い（レポートに入るもの）
- いちばん得点を左右した判断は何か。エネルギーとレールの配分の言葉で説明しよう
- 缶に当てるために、何に向けて飛ばしたか。それで当たる理由を説明しよう
- 「理想の点」と「平均点」に差が出たのはなぜか。差を小さくするために何を変えたか

## ヒントのしくみ
- 各問いに3段階のヒントを用意し、生徒が自分で開く
  - ヒント1：見る場所を示す（例：「ループの頂上で、棒グラフの K はどれくらい残っている？」）
  - ヒント2：比べ方を示す（例：「ループの最下点を10 cm 低くして、もう一度走らせてみよう」）
  - ヒント3：式とのつながりを示す（例：「頂上で落ちない速さは v² ≥ gr。そこまでに必要な高さの差は？」）
- 開いたヒントの段階はレポートに残す（評価ではなく、自分の振り返り用）

## 画面一覧
- スタート：ルール（得点表と制約）、予想入力、全体の流れと進み具合
- 練習ステージ（3つで共通の型）：上にコース（横から見た図）、右または下に K・U・T の棒グラフ、その下に問い・入力欄・ヒント
- 設計画面：部品ごとの設定（スライダーと切り替え）、横から見たコースの図、残りのレールのメーター、各地点の速さの目安
- 試走画面：アニメーション、得点の内訳、失敗理由の候補、「1回走らせる」「10回連続」
- 記録表：試走ごとの設計のちがい・得点（1回／10回平均）・成功率・変更の理由
- レポート：全体のまとめ、印刷用レイアウト、コピーボタン

## データと公開範囲（保存の有無・ログインの有無・個人情報）
- 保存：その端末のブラウザ（localStorage）だけ。サーバーには送らない。Firebase は使わない
- ログイン：なし。名前の入力欄も置かない（提出先の Classroom などで誰のものかわかるため）
- 個人情報：入力するのは予想・理由・振り返りだけ。自由記述欄に「名前や連絡先は書かない」と添える
- 「最初からやり直す（記録を消す）」ボタンを置く
- 一般公開（URLを配るだけで使える）。サブドメインの候補：`coaster-mission.meetupsensei.com`

## 試作で確かめたいこと（AI Studio Build で見たい点）
- 試算どおり、どの戦略でも平均点が近く、全部入りが組めないか。定数（レール6 m・損失1.5 cm/m・ループ損失5%・ばらつき）で手応えを調整する
- **缶の高さが、いつも最上段（＋50）一択にならないか**。モンキーハンティングでは高さによらず当たるため、試算では最上段が常に有利だった。必要なら「高い缶ほど発射台から遠い」「発射台の高さに上限」などで調整する
  - → 対応済み（2026-10-20）：高い缶ほど遠くに置き、左右のずれを距離に比例させた。最上段の得は平均1〜5点に縮んだ（`docs/balance.md`）
- 横から見たコースの図が、スマホの縦画面でも高さの違いがわかる大きさで描けるか
- 「缶へまっすぐ向けると当たる」が、練習ステージの中で自然に見つかるか
- 10回連続のばらつきの大きさが、「余裕を持たせると成功率が上がる」と感じられる程度か
- 転がる球とすべる物体の切り替えで、違いが見てわかるか
- レポートを印刷・PDF保存したときに、図と表が崩れないか

## やらないこと
- 実物のコースづくりの手順や、実測値の入力
- 部品を自由に並べ替えるエディタ（順番は固定）
- 坂の傾きを変える機能（30°に固定。発展版の候補）
- 班での共同編集・同期、教師による集計やランキング（Firebase を使わない）
- ログイン、クラウド保存
- AI による自動採点・説明文の判定（説明の良し悪しは授業で扱う）
- 3次元のコース設計（コースは横から見た2次元。左右のずれは、ばらつきとしてだけ扱う）
- 既存の coaster.meetupsensei.com への区間追加（別アプリとして作る）

## 反映した教訓
- 主役のモードを最初に決める → 1人1台のソロを主役に固定し、班での共有や教師の集計は「やらないこと」に入れた（2026-10-02 lemonade-game-v2）
- 仕様を先に1枚にまとめてから頼む → 制約・数値・得点・流れ・レポートを、このファイルに全部まとめた（2026-10-02 lemonade-game-v2）
- 「考えなくても勝てる」状態を避ける → レールを6 mに限り、坂が高さの分だけレールを使うようにした。本番の記録を10回連続の平均点にして、ぎりぎりの設計が有利にならないようにした。試算で、戦略ごとの平均点が近いことを確かめた（2026-10-02 lemonade-game-v2）
- 専門用語を避けた呼び名 → 「モンキーハンティング」は解説の中だけで使い、画面では「缶へまっすぐ向ける」と書く。エネルギーは「運動 K」「位置 U」「熱など T」のように、日常語と記号を並べる（2026-10-02 lemonade-game-v2）
