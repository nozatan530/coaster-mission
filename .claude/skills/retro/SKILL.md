# 振り返り

入力: $ARGUMENTS

1. 足りなければ、次の観点で2〜3問だけ聞く。
   - いつ・どこで・誰が使ったか（例：高1物理、40人、Chromebook）
   - うまくいったこと／つまずいたこと（生徒の反応、操作で迷った所、不具合）
   - 学びの目的（docs/concept.md）に対して、どうだったか
2. `docs/retro.md` の先頭に追記する（新しいものが上）。

```markdown
## yyyy-mm-dd <場面>
- 使った人・端末:
- うまくいった:
- つまずいた:
- 学びの目的に対して:
- 次にやること（このアプリ）: → spec.md の実装タスクへ
- 次のアプリへの教訓: → ~/code/ideas/LESSONS.md へ
```

3. 「次にやること」を `docs/spec.md` の実装タスクにチェックリストとして追加する（重要な順）。
4. 「次のアプリへの教訓」があれば、`/Users/nozkoh/code/ideas/LESSONS.md` の該当する見出しの下に1行ずつ追記する（日付とアプリ名を付ける）。同じ趣旨の行がすでにあれば、追記せず件数を増やす。
5. コミットして、最後に3行で伝える：記録したこと／追加したタスク数／LESSONS.md に足した教訓。
6. note の制作記になりそうな気づきがあれば、1行で提案する（書くかどうかはユーザーが決める）。
