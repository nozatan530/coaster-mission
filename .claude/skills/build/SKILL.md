# 実装

対象: $ARGUMENTS

## 初回だけ

`docs/spec.md` に「実装タスク」節がなければ、concept.md と spec.md から、1つ30分〜1時間で終わる粒度のチェックリストを作って確認を取る。
技術スタックが CLAUDE.md で未記入なら、候補を1〜2個示して決めてもらい、CLAUDE.md の「技術スタック」「コマンド」を埋める。

## 毎回

1. 対象タスクを1つ選び、何を作るかを2〜3行で宣言する。
2. 実装する。守ること:
   - AI 呼び出しはサーバー側（Functions など）に置く。フロントは自前の API だけを叩く。
   - プロンプト・スキーマ・モデル設定は `prompts/<機能名>/` から読み込む。コードに文字列で埋め込まない。
   - 返ってきた JSON はスキーマで検証し、失敗時は spec.md の「失敗時の扱い」どおりにする。
   - 狭い画面（幅 360px）で崩れないこと。
3. 型チェック・テスト・ビルドが通ることを確認する（コマンドは CLAUDE.md）。
4. spec.md のチェックリストを更新し、日本語のメッセージでコミットする。
5. 残りタスクと、`/verify` をかけるべきタイミングかどうかを1行で伝える。

正本（prompts/ の3ファイル）を変えたくなったら、実装で回避せず理由を示して止まる。
