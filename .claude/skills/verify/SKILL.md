# 検証

重点: $ARGUMENTS

## 1. 自動チェック

CLAUDE.md の型チェック・テスト・ビルドを実行。失敗があれば先に直す。

## 2. ブラウザで実操作

開発サーバーを起動し、使えるブラウザ操作手段（Claude in Chrome、Playwright など）で concept.md の「体験の流れ」を最初から最後までたどる。
画面幅は 360px（スマホ）・768px（iPad）・1366px（Chromebook）の3つで確認し、スクリーンショットを `docs/verify/` に保存する。

見ること:
- 体験の流れが途中で止まらないか
- 表示崩れ、はみ出し、押しにくいボタン
- コンソールエラー、失敗しているネットワークリクエスト
- AI 機能: 典型入力で期待どおりか／待ち時間の表示があるか／失敗時の表示が出るか

## 3. 安全面の確認

- ビルド成果物（dist 等）に `GEMINI_API_KEY` や `AIza` で始まる文字列が含まれていないか grep する。
- ブラウザのネットワークタブで、Gemini API へ直接リクエストしていないか確認する。
- 個人情報を入力欄に入れたとき、API に送られていないか（または送られない設計か）確認する。

## 4. レポート

`docs/verify/<yyyy-mm-dd>.md` に、OK／要修正／気になる点の3区分でまとめる。
要修正は、次に `/build` で直すタスクとして spec.md のチェックリストに追加する。
